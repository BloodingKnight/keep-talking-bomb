# 页面设计：按"块（block）"组织，按屏幕尺寸决定同时看几块

> 目标：每个屏幕只专注一件事（一块）；但电脑上可以并排看多块。
> 本文是**设计稿**，实现前先对齐；实现清单在最后一节。

---

## 一、先把"块"分清楚

界面里真正需要用户注意的内容只有五类，所有角色都是这五块的子集：

| 块 | key | 内容 | 谁最需要 |
|---|---|---|---|
| **主区** | `main` | 炸弹模块 / 专家手册 / 盲操轮廓（按角色决定） | 全部 |
| **状态** | `status` | 倒计时、失误灯、存活人数、阶段 | 操作者、聋桥猴 |
| **信号** | `signals` | 手势/信号按钮 + 最近信号 | 哑手册猴、聋桥猴 |
| **聊天** | `chat` | 文字频道（不能说话的玩家靠它） | 静默操作员、哑手册猴 |
| **邀请** | `invite` | 房间号 + 二维码（仅准备阶段） | 房主 |

大厅（准备阶段）的块：`players`（玩家+邀请）/ `roles`（角色卡+预设）/ `settings`（难度/模块数/手册）/ `chat`。

**主区的标题随角色变**（这是关键：不是给每种角色做一套界面，而是一套块 + 角色决定"主区里放什么"）：

| 角色 | 主区标题 | 图标 | 默认块 |
|---|---|---|---|
| 拆弹者 / 静默操作员 | 炸弹 | 💣 | main |
| 盲操猴 | 轮廓 | 🧭 | main |
| 专家 / 盲眼观察员 / 专家 II·III | 手册 | 📖 | main |
| 哑手册猴 | 手册 | 📖 | main |
| 聋桥猴 | 炸弹 | 💣 | main（他还要盯着信号） |

所以**五块是固定的**，只有"主区的内容"和"标签顺序"按角色变化 —— 实现量可控，也不会出现"某个角色少一块"的怪状态。

## 二、三种屏幕，三种同时可见块数

### 手机（< 640px）：一次一块 + 底部标签栏

```
┌──────────────────────────────┐
│ 💣 保持沟通…   房间 7K2M  🙉  │  ← 顶栏（可滚动，次要徽标在手机上省略）
├──────────────────────────────┤
│ ⏱ 04:32   ✖ 0/3   ● 3 人在线 │  ← 常驻迷你状态条（40px，任何块下都可见）
├──────────────────────────────┤
│                              │
│                              │
│        当前块（唯一可见）      │  ← 占满剩余高度，内部自己滚
│                              │
│                              │
├──────────────────────────────┤
│  💣炸弹  ⏱状态  ✟信号  💬聊天 │  ← 底部标签栏（56px + 安全区，拇指可达）
└──────────────────────────────┘
```

- 一次**只显示一块**，其余 `display:none`（不是滚出屏幕，是真的不占位置）
- 标签顺序按角色重排，**主区永远第一个**
- 底部标签栏固定，**不随内容滚动**
- 迷你状态条常驻：切到手册时也能看到剩余时间（专家要边查表边说"还有 40 秒"）
  - 盲操猴例外：他只看到失误灯，不显示数字时间（和现有信息设计一致）
- 每块的滚动位置**独立记忆**，切回来还在原处

### 平板（640–1024px）：两块，主区 + 一个可切换的侧栏

```
┌──────────────────────────────────────────┐
│ 💣 保持沟通…            房间 7K2M  🙈     │
├──────────────────────────────────────────┤
│ ⏱ 04:32  ✖ 0/3  ● 3 人                   │
├───────────────────────────┬──────────────┤
│                           │ [状态|信号|聊天] │ ← 分段控件选侧栏内容
│         主区               │              │
│      （约 68% 宽）          │   侧栏 32%    │
│                           │              │
└───────────────────────────┴──────────────┘
```

- 主区始终在左（宽的那半），侧栏可切三种内容
- 平板横屏用这个；竖屏时退化为手机的单块+标签（宽度 < 640px 时）

### 电脑（> 1024px）：三块并排（现状的基础上加强）

```
┌────────────────────────────────────────────────────────────────┐
│ 💣 保持沟通…   房间 7K2M  🙉 聋桥猴        [专注模式] [教程]   │
├────────────────────────────────────────────────────────────────┤
│ ┌──────────────┐  ┌──────────────────────┐  ┌────────────────┐ │
│ │ 状态          │  │ 主区（炸弹/手册）     │  │ 信号 + 聊天     │ │
│ │ ⏱ 04:32      │  │                      │  │ 🤟 最近信号     │ │
│ │ ✖ 0/3        │  │      （最大面积）      │  │ ─────────────  │ │
│ │ 玩家在线      │  │                      │  │ 💬 文字频道     │ │
│ └──────────────┘  └──────────────────────┘  └────────────────┘ │
└────────────────────────────────────────────────────────────────┘
```

- 默认**三块全部可见**（这是现在电脑版的体验，保留）
- 右上角「专注模式」：切换成单块 + 顶部标签栏（和手机同一套机制），适合屏幕小或想少分心的玩家
- 快捷键（专注模式下）：`1..4` 切块，`Esc` 退出专注，`F` 切换专注

## 三、大厅（准备阶段）怎么排

同样五块→四块：

| 块 | 手机标签 | 内容 |
|---|---|---|
| 玩家 | 👥 玩家 | 玩家列表 + 邀请二维码 + 踢人/退出 |
| 角色 | 🎭 角色 | 预设（三人经典等）+ 角色卡 |
| 设置 | ⚙️ 设置 | 难度 / 模块数 / 手册分配 / 开始 |
| 聊天 | 💬 聊天 | 文字频道 |

- 手机默认停在「角色」（新进来第一件事是选角色）
- 房主开局前的最后一步在「设置」里，标签上给个提示点（●）
- 二维码放在「玩家」块顶部（手机扫的是别人，所以房主在电脑上看这个块）

## 四、交互细节（这些是最容易被忽略、但决定手感的）

1. **不做左右滑动切块**：炸弹里有旋钮、剪线、拖动，滑动手势会和操作冲突。只提供点标签。
2. **标签点按区域 ≥ 44px**，图标在上、文字在下（中文两字），当前块加高亮下划线 + 颜色。
3. **切块不重渲染**：五块始终在 DOM 里，只切 `display`；这样炸弹的动画/闪烁序列不会被重启动（我们已经有 renderKey 机制，但切块更不该触发）。
4. **主区标题按角色显示**（炸弹/轮廓/手册），不是"面板1"。
5. **未读提示**：不在聊天块时，聊天标签显示未读小点；不在信号块时同理。
6. **滚动位置记忆**：每块独立保存（内存即可，刷新后重置到顶）。
7. **迷你状态条**：只在手机/平板显示；电脑上状态块里本来就有，避免重复。
8. **平板分段控件**：侧栏内容切换不改变主区宽度（避免内容重排抖动）。
9. **安全区**：底部标签栏 `padding-bottom: env(safe-area-inset-bottom)`。
10. **横屏手机**（高度 < 480px）：自动隐藏迷你状态条，把高度让给内容。

## 五、实现清单（确认设计后按这个做）

1. **`client/panes.js`（新，纯逻辑、可单测）**
   - `PANES`：五个块的 key/图标/标签
   - `panesForRole(role)`：返回该角色的块顺序（主区永远第一）
   - `mainTitleForRole(role)`：炸弹 / 轮廓 / 手册
   - `LOBBY_PANES`：四块
   - `isSinglePaneLayout(width)`：断点判定

2. **`client/index.html`**
   - 游戏区三个块加 `data-pane="status|main|chat"`，并把左侧栏拆成「状态」和「信号」两块
     （用 `display:contents` 让左侧栏在手机上不成为一个盒子，其子元素各自成块）
   - 大厅四个面板加 `data-pane`
   - 每个有标签的 stage 末尾加 `<nav class="pane-tabs">`（JS 填按钮）
   - 顶栏加「专注模式」按钮（桌面显示）

3. **`client/app.js`**
   - `mountTabs(stageEl)`：按角色生成标签、绑定切换、记忆上次块
   - 媒体查询监听：`matchMedia('(max-width: 639px)')` / `(max-width: 1023px)` 切换布局模式
   - 迷你状态条渲染（复用现有 HUD 数据，盲操猴不显示数字时间）
   - 未读点、滚动记忆、键盘快捷键

4. **`client/style.css`**
   - 三段断点：`<640` 单块+底部标签、`640–1023` 主区+侧栏、`>1023` 三栏
   - `.pane-tabs`、`.mini-hud`、`.focus-mode`、未读点、安全区
   - 现有 760px 那层保留给"平板竖屏"，与新断点合并整理

5. **测试**
   - `tests/panes.mjs`：角色→标签顺序/默认块/主区标题的单测；
     `index.html` 里五块 `data-pane` 齐全、每个 stage 有 `.pane-tabs`、
     标签数量与 `panes.js` 一致（防止"少一块"）
   - `tests/mobile.mjs` 扩展：标签栏 44px、迷你状态条存在、安全区
   - 回归：18 个套件全绿
