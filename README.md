# 保持沟通就没人爆炸（本地合作拆弹）

一个**本地多人、信息不对称**的合作拆弹游戏：一个人只能看到炸弹，其他人只能看到手册，
剩下的一切都靠你们自己当面沟通。

- 零第三方依赖，只用 Node.js 自带模块（HTTP + SSE）实现
- 同一台电脑或同一个局域网，每人用自己的手机 / 平板 / 电脑开一个浏览器标签加入
- 不提供语音/视频：语音靠你们自己（当面说、开语音），不能说话的玩家用游戏内**文字频道**
- 关卡按难度自动生成，答案是随机表，不是背下来的

> 本项目是为了复刻「一个人看炸弹 + 其他人查手册」这种**合作沟通玩法**而写的原创实现。
> 所有规则表、模块设计、界面文案都是为本项目写的原创内容。
> 附件里的《Keep Talking and Nobody Explodes》官方手册只被用来理解这类玩法的结构，
> 手册正文没有被复制进本项目的任何文件。

## 快速开始

最简单：**双击 `start.cmd`**（Windows），或者在终端里跑：

| 平台 | 命令 | 说明 |
|---|---|---|
| Windows | `start.cmd` | 双击也行；默认 3210，启动后自动开浏览器 |
| Windows | `start.cmd 8080` | 换端口 |
| Windows | `start.cmd 3210 -AdminToken 我的令牌` | 固定管理入口令牌 |
| Windows | `start.cmd 3210 -Detached` | **后台运行**（日志写 `server.log`，关掉窗口不影响） |
| Windows | `.\stop.ps1` | 停掉后台模式起的服务（`-Port 8080` 可换端口） |
| macOS / Linux | `./start.sh`、`./start.sh 8080` | 加 `--nobrowser` 就不自动开浏览器 |

> 脚本只是包装，最后都会执行 `node server/server.js <端口> [参数]`，直接跑 node 也一样。
> `start.cmd` / `start.ps1` 还支持 `-NoBrowser`（不开浏览器）、`-Test`（测试模式，正常玩不要加）。
> 后台模式的日志在 `server.log`，管理令牌也能从里面翻出来。

手动启动（不使用脚本）：

```bash
# 需要 Node.js 18+（无任何第三方依赖，不需要 npm install）
node server/server.js            # 默认端口 3210
node server/server.js 8080       # 也可以指定端口
```

启动后终端会打印本机地址。让每个人用自己的设备打开：

- 同一台电脑：`http://localhost:3210`
- 局域网内其他设备：`http://<这台电脑的局域网IP>:3210`

第一个人直接点「加入 / 新建」就会创建房间，把房间号（或「复制邀请链接」）发给其他人即可。

> Windows 上如果别的设备连不上，检查防火墙是否允许 Node.js 监听该端口。

## 一局游戏怎么玩

1. **房主**在准备区选难度，并点「开始拆弹」。
2. 每个人在准备区选自己的角色：
   - **拆弹者**：屏幕上是炸弹，能动手，**看不到任何手册**
   - **专家**：屏幕上是手册和炸弹外壳信息（序列号、电池、指示灯、端口），**看不到炸弹**
   - **盲眼观察员**：手册只有一部分条目，必须和别的专家拼信息
   - **静默操作员**：和拆弹者一样能看炸弹、能操作，但不能说话，只能用文字频道
   - 3 人以上会自动出现**专家 II / 专家 III** 座位
3. 拆弹者把屏幕上的细节念出来（颜色、顺序、数字、闪烁的长短和节奏、按钮上的字）。
4. 专家查表，把结论告诉他（剪第几根、按什么颜色、在计时器显示几时松手……）。
5. 模块全部拆完即胜利；**失误达到上限**或**倒计时归零**即爆炸。

### 角色与座位规则

| 角色 | 看炸弹 | 拿手册 | 能操作 | 能说话 | 备注 |
|---|---|---|---|---|---|
| 拆弹者 | ✅ | ❌ | ✅ | ✅ | 精确倒计时可见 |
| 专家 | ❌ | ✅ 完整 | ❌ | ✅ | 手册 + 外壳信息 |
| 盲眼观察员 | ❌ | ✅ 一部分 | ❌ | ✅ | 拆分手册，需要和其他专家拼 |
| 静默操作员 | ✅ | ❌ | ✅ | ❌ | 只能用文字频道 |
| 专家 II / III | ❌ | ✅ 一部分 | ❌ | ✅ | 4 人以上自动开放 |
| 🙈 盲操猴 | ✅ **只有轮廓** | ❌ | ✅ | ✅ | 三人经典：看不见颜色/数字/文字，也看不到倒计时 |
| 🙉 聋桥猴 | ✅ 完整 | ❌ | ❌ | ✅ | 三人经典：看得见整颗炸弹、信号，还能看到盲操猴的鼠标在点哪 |
| 🙊 哑手册猴 | ❌ | ✅ 完整 | ❌ | ❌ | 三人经典：有手册，只能说信号/打字 |

- 「拆弹者 / 静默操作员 / 盲操猴」占同一个**动手座位**，同一房间只会有一个；
- 专家座位共 3 个（拆弹者之外的每个人都能当专家，含聋桥猴 / 哑手册猴）；
- 加入时如果指定角色已被占用，会**先把你放在空位上**，你可以在准备区自己点角色卡换。

### 难度

| 难度 | 模块数 | 倒计时 | 失误上限 | 每次失误罚时 | 手册 |
|---|---|---|---|---|---|
| 简单 | 3 | 300s | 5 | −15s | 完整 |
| 普通 | 4 | 300s | 3 | −20s | 完整 |
| 困难 | 5 | 270s | 3 | −25s | 完整 |
| 专家 | 6 | 210s | 2 | −30s | 拆成两半分给不同专家 |
| 噩梦 | 7 | 240s | 1 | −30s | 拆成两半分给不同专家 |

难度同时控制**模块等级（tier 1~5）的权重**：简单几乎只出低等级模块，
噩梦全是高等级模块（规则更长、依赖更多外壳信息）。

### 计分

```
得分 = 已拆模块 × 100 + 剩余秒数 × 3 − 失误次数 × 50 + (零失误 ? 250 : 0)
```

失败的局只保留「已拆模块 × 100」的基础分。

## 模块与手册

每个模块都是「\*\*炸弹上看到一部分 + 手册上看到另一部分\*\*」，必须两边配合才能拆。目前共 **18 个模块**。
模块实例会随机生成，同一模块每次的表都不一样（不能背表），并且大量规则依赖炸弹外壳信息
（序列号是否含元音、末位奇偶、电池数量、指示灯、端口）。

| 模块 | 等级 | 炸弹上看到 | 手册上看到 |
|---|---|---|---|
| 线缆 🪢 | 1–3 | 3~6 根线的颜色与位置（高等级可能带条纹） | 按顺序检查的条件表（红线几根、末位奇偶、电池、指示灯、端口…） |
| 按钮 🔘 | 1–2 | 按钮颜色和文字 | 「按住还是轻按」的判定表 + 「按住后按光条颜色决定何时松手」表 |
| 符号键盘 ⌨️ | 2–4 | 4 个符号格 | 三列符号，只有一列完整包含键盘上的四个符号；按该列的上下顺序按 |
| 闪光序列 🚦 | 1–5 | 按节奏依次闪烁的颜色 | 闪烁颜色 → 要按按钮颜色的换算表（含元音/失误次数分支） |
| 记忆 🧠 | 2–5 | 屏幕数字 + 四个带数字的按钮，共 5 个阶段 | 五个阶段各自「显示几 → 按第几个」的表；按错回到阶段 1 |
| 摩斯电报 📻 | 2–5 | **一个单词** + 电报机（· 点 / — 横 键盘、纸带） | 摩斯对照表 + **逐字母拆解表**（把单词翻成点横序列念给拆弹者） |
| 迷宫 🌀 | 3–5 | 光点位置 + 终点的**大致方向与行列差**（看不到墙） | 6×6 迷宫的**墙分布图** |
| 密码 🔤 | 4–5 | 5 个字母转轮 | 可拼单词表（只有一个组合在表里） |
| 逻辑问答 ❓ | 2–5 | 一个问题 + 四个选项 | 炸弹外壳信息 + 选项（答案要专家自己算） |
| 齿轮传动 ⚙️ | 3–5 | 一串互相咬合的齿轮（数量和齿数）+ 第一枚的转向 | 「奇数个反向 / 偶数个同向」+ 第一枚转向的判定（高等级还要看末位奇偶再翻一次） |
| 天平配重 ⚖️ | 4–5 | 左右秤盘、各自配重的重量与距支点格数 | 力矩算法与「右边该放几个」的结论 |
| 十进制解码 🔢 | 4–5 | 两串二进制数字 + 一个运算符号 | AND / OR / XOR / 加 的定义 + 二进制转十进制换算表 |
| 三色电报 🚨 | 3–5 | **一个单词** + 红/黄/蓝三条灯带 + 电报机 | **逐字母表**：第几个字母走哪条灯带、电码是什么 |
| 复杂线路 🧵 | 3–5 | 4~5 根带条纹/★/LED 的线，每根线上写着字母 | 字母含义表（C 剪、D 不剪、S 看末位偶、P 看 Parallel 端口、B 看电池）+ 逐根判定 |
| 电容放电 🔋 | 3–5 | 充电条 + 7 格刻度 + 秒表 | 周期长度与「第几秒拉下拉杆」的时机表 |
| 保险柜旋钮 🔒 | 4–5 | 00~99 的旋钮与三位输入 | 三位密码的推算规则（含序列号元音/末位） |
| 字母键盘 🔠 | 5 | 一串**移位过的**字母 + 26 键键盘 | 移位量，要求还原成口令 |
| 双序列闪光 🎇 | 4–5 | 两段闪烁（第一段较慢、第二段较快） | 两张换算表（表 A / 表 B），分别对应两段 |

手册页面还提供：**外壳信息条**（序列号 / 电池 / 指示灯 / 端口 / 当前失误）、颜色图例、关键字搜索。

### 在线管理入口 `/admin`（推荐用来验题）

服务器启动时会在终端打印一个带令牌的管理地址：

```
[bomb] 管理入口（只有你知道，别外传）:
[bomb]   http://localhost:3210/admin?token=xxxxxxxx
```

打开它就是**管理面板**，三个标签页：

| 标签 | 能做什么 |
|---|---|
| 🧪 **出题与视角** | **验题 + 角色视角合并成一页**。先选题目来源：<br>• **单个模块**：选「模块 + 等级」出题，默认并排显示**🧰 操作者视角（可以直接点着玩，判定和正式游戏一致）**和**📖 专家手册**<br>• **整颗炸弹**：选难度和模块数，生成一颗完整炸弹<br>然后在下方的**视角多选条**里自由加/减：盲眼观察员、静默操作员、**盲操猴（界面只有白色轮廓）**、聋桥猴、哑手册猴、专家 II、真相（题目+答案）、全选 / 只留操作者+专家。<br>其中**聋桥猴**那一栏会把**整颗炸弹**（所有模块）一起渲染出来，用来复刻他"看得见全貌"的权限；如果同一时刻盲操猴也在某个模块上动，聋桥猴那一栏还会画出**幽灵光标**（跟着刷新）。<br>按住类按钮在测试台里会附带一个**测试用计时器**，所以松手时机也能真的验。<br>还有「**一键全量自检**」：18 个模块 × 5 个等级 = 90 道题全部生成一遍，检查题目状态、手册规则块、空表格、迷宫墙一致性、键盘唯一解 |
| 🚪 **房间监控** | 列出所有房间：阶段、难度、进度（已拆/总数）、剩余时间、失误数、每个玩家的角色与在线状态、各模块状态；可以**踢人**、**关闭房间**、把倒计时**一键压到 10 秒**（用来验证爆炸/超时流程） |
| 📊 **服务器状态** | 运行时长、Node 版本、房间数/在线人数、是否测试模式、临时题目缓存量，以及各难度档位参数 |

- 令牌每次启动随机生成；也可以用 `--admin-token=你的令牌` 或环境变量 `BOMB_ADMIN_TOKEN` 固定下来
- 所有 `/api/admin/*` 接口都校验令牌，不带或带错一律 `401`
- 令牌会存在浏览器 sessionStorage 里，刷新不用重输；也可以直接改 URL 上的 `?token=`
- 管理面板里的操作**完全不影响正在进行的游戏**（用的是独立的临时题目）

游戏内准备区也保留了同样的「模块测试台」按钮给房主用 —— 两处共用同一套生成与判定逻辑。

### 三人经典配置：不看 / 不听 / 不说

参考 Steam 上的《BOMBANANA!》（三只猴子：不见、不听、不言，[Steam 商店页](https://store.steampowered.com/app/4656000/BOMBANANA/)），
准备区可以一键套用「**三人经典**」预设，三个人的权限正好互相残缺：

| 角色 | 看得到 | 看不到 | 能做 | 不能做 |
|---|---|---|---|---|
| 🙈 **盲操猴** | 只有模块的**白色轮廓**（能点、能操作） | 颜色、数字、文字，以及倒计时 | 操作炸弹 | 看题面、看手册 |
| 🙉 **聋桥猴** | **整颗炸弹**（全部模块的题面、颜色数字）、倒计时、队友的**手势信号**，以及盲操猴**鼠标停在哪、点了哪** | 听不见任何人说话（请自觉） | 说话转述、发信号 | 操作炸弹、看手册 |
| 🙊 **哑手册猴** | 手册 + 外壳信息、队友信号 | 看不到炸弹 | 查手册、发信号、打字 | 说话（请自觉闭嘴）、操作炸弹 |

配套的**手势 / 信号**面板（游戏界面左侧）就是"中间商式沟通"的载体：哑手册猴点一个信号（`1` `2` `3` `🔴 红` `✅ 对` …），
聋桥猴**看得见**这条信号，盲操猴**看不见**（他只听得见喊），于是形成了设计里的那条链路：

```
哑手册猴（手册）──信号/打字──▶ 聋桥猴（看得见炸弹 + 信号 + 盲操猴的鼠标）──口头喊──▶ 盲操猴（盲操作）
```

- 盲操猴**没有精确倒计时**，时间要由聋桥猴报给他
- 盲操猴**收不到信号**（"看不见"），只能靠聋桥猴喊
- 聋桥猴拿到的是**整颗炸弹的完整界面**（不是轮廓），而且上面会浮着一个**幽灵光标**：
  盲操猴的手指点在哪个模块、鼠标停在格子里的哪个位置，聋桥猴几乎同步看得到 ——
  这样"他点到哪了 / 他想点哪个"就不需要盲操猴自己描述，聋桥猴可以直接喊「往右一格」「那个就是红色按钮」
- 幽灵光标只会画在**盲操猴正在看的那个模块**上，并且带一个小标签写着是谁在操作
- 想同时要"两个半本手册"就套用「四人：盲操 + 聋桥 + 两个哑手册」，手册会拆成两半

> 另外保留了传统角色（拆弹者 / 专家 / 盲眼观察员 / 静默操作员），准备区里都能直接选。

### 各角色怎么玩 / 怎么单人试玩

| 角色 | 能看什么 | 该怎么玩 |
|---|---|---|
| **拆弹者** | 只有炸弹（模块题面 + 倒计时 + 失误灯） | 把看到的一切**念出来**：颜色、顺序、字母、闪烁的长短和节奏、按钮上的字。听指令动手 |
| **专家** | 只有手册 + 炸弹外壳信息（序列号/电池/指示灯/端口） | 主动**问清楚**外壳信息，再查表 → 把指令说成一句能执行的话 |
| **盲眼观察员** | 手册的**一部分条目**（同一个座位每次都是同一批） | 先报"我这边有哪几页/哪几行"，再和其他专家**互相补全**；缺的那半条要问别人 |
| **静默操作员** | 和拆弹者一样（炸弹 + 能操作），但**不能说话** | 用游戏内**文字频道**打字：把看到的信息发给专家 |
| **专家 II / III** | 手册的另一半 | 和盲眼观察员配合，把两张半表拼起来 |

**单人怎么试玩**：打开管理入口 →「**🧪 出题与视角**」，默认就是"操作者 + 专家"两个视角并排。
照着演一遍即可：先看操作者那一栏把信息念出来（或自己记下），再用专家那一栏当手册查表，
把指令填回操作者那边对应的操作。想体验别的角色，就在视角条上把他们加上 ——
比如加上「🙈 盲操猴」就能看到"只有白色轮廓"的画面，加上「🙈 盲眼观察员」能体验"信息不全时怎么问"，
加上「🙉 聋桥猴」则是**整颗炸弹一起铺开**（配上盲操猴视角就能看到幽灵光标）。
只想练单个模块，就把题目来源切成「单个模块」。

**多人怎么分配**：
- 2 人：拆弹者 + 专家
- 3 人（**推荐**）：套用「三人经典」—— 盲操猴 + 聋桥猴 + 哑手册猴，三种感官各缺一个，必须转述
- 3 人（传统）：拆弹者 + 专家 + 盲眼观察员
- 4~6 人：套用「四人：盲操 + 聋桥 + 两个哑手册」（手册拆成两半互相念），或再加专家 II / III

### 房主的「模块测试台」

准备区有「**模块测试台**」按钮（只有房主可见），用来验题：

- 任意选**模块 + 等级**，点「换一道题」现场生成一道新题
- 左边是**拆弹者看到的题目**（可以直接点着玩：做对了标绿，做错了提示"会记一次失误"）
- 右边是**同一道题的专家手册**（含外壳信息），一眼核对"题面和规则是否对得上"
- 完全隔离：不会往准备区塞炸弹，也不影响正式游戏

> 按住类按钮在测试台里**不判失误**（那里没有真实倒计时），但会告诉你"正式游戏里应该在计时器显示几时松手"。

### 拆分手册

困难及以上（或被房主强制）时，每个模块**承载答案的那张表**会被切成几份，
按座位分配，且分配是稳定的：同一个座位每次看到的都是同一批条目。
两个专家必须互相把关键行念出来 —— 这就是三人以上合作的乐趣所在。

## 退出 / 关闭房间

| 你想做的事 | 怎么操作 | 行为 |
|---|---|---|
| 我不想玩了，想退出 | 右上角「退出房间」（准备区里也有一个） | 准备阶段：直接离开房间。游戏进行中：座位保留、标记离线，其他人可以继续；刷新页面能重连回来 |
| 我是房主，这一局不玩了 | 右上角「关闭房间」（只有房主看得到） | 所有人都收到通知并回到主界面，房间立刻从房间列表消失 |
| 把某个人踢出去 | 准备区点一下那个玩家，再点「移除选中玩家」 | 那人立刻被请出房间，座位空出来 |
| 房主自己退了 | —— | 房主自动转给房间里下一个在线的人 |
| 最后一个人退了 | —— | 空房间自动回收，房间号立即可再次使用 |

关闭标签页 / 关掉浏览器不算"退出"：那只是断线，座位会保留（准备阶段 30 秒、游戏进行中 30 分钟），
刷新或重新打开原链接就能回到原座位。

## 会话与联机细节

- **房间号**：4 位大写字母数字（去掉了易混淆的 O/0/I/1），点房间号即可复制邀请链接 `/?room=XXXX`
- **断线重连**：玩家 id 存在 sessionStorage，刷新页面会自动回到原座位；SSE 断开时右上角会提示并自动重连
- **主动退出**：`leave` 会把自己移出（准备阶段）或标记离线（游戏中，保留座位）；房间空了自动回收
- **房主关闭**：`closeRoom` 会给房间里每个人推一条 `event: closed`，客户端收到后清掉本地会话回主界面
- **实时同步**：`GET /api/events` 的 Server-Sent Events 推送（每秒心跳一次，倒计时和状态都是服务端权威）
- **文字频道**：`POST /api/action {type:'chat'}`，给不能说话的玩家用，也方便传精确情报
- **队友光标**：`cursor` 动作把操作者的鼠标位置（归一化 0~1）广播给同房间的聋桥猴 / 哑手册猴，
  坐标在服务端夹取到 0~1；盲操猴自己的视图里**不带**任何光标（他反正看不见）
- **服务器权威**：所有答案只存在服务端内存里。给专家的视图里**根本没有**模块内部状态，
  给拆弹者的视图里**根本没有**规则表；客户端算不出答案，只能靠沟通

## 分发：发给别人玩（不用装 Node）

### 想立刻分享（家里没有公网 IP）

游戏服务跑在你自己的电脑上，用一条隧道把它映射成公网地址即可，**不需要公网 IP、不用路由器端口映射**：

```bash
node tools/share.mjs            # 自动挑工具，端口默认 3210
node tools/share.mjs 3210 --tool cloudflared
```

它会打印一个 `https://xxxx.trycloudflare.com` 之类的地址，发给朋友就能玩。三条路（脚本会自动按顺序试）：

| 工具 | 要不要注册 | 说明 |
|---|---|---|
| **cloudflared** | 不用 | 最省事，`cloudflared tunnel --url http://127.0.0.1:3210` 就有公网 https 地址 |
| ngrok | 要（免费） | `ngrok config add-authtoken <token>` 之后同样一条命令 |
| localtunnel | 不用 | 纯 `npx localtunnel --port 3210`，不用装东西；首次访问可能要填一次密码（你自己的公网 IP） |

国内网络如果下载 cloudflared 困难，用国内的内网穿透（natapp / cpolar / 花生壳）也一样，
把隧道指向 `http://127.0.0.1:3210` 即可 —— 脚本能识别 cpolar / natapp 的地址格式。

**关键细节**：用隧道地址打开游戏后，**大厅里的二维码会自动变成公网地址**（不再给局域网 IP），
所以朋友扫码直接能进，不用你解释"要连同一个 Wi-Fi"。

> 隧道地址每次重启都变。想要固定地址就往下看「公网在线版」，把服务部署到云主机。

### 方式一：单个 exe（最省事，面对面玩）

```bash
node tools/build-single.mjs
# -> dist/BombGame.exe                   （91 MB，双击即玩，旁边不需要任何文件）
# -> dist/BombGame-win-x64-single.zip    （35 MB，里面只有那一个 exe）
```

用 **Node SEA（Single Executable Application）** 把整个游戏嵌进 `node.exe`：

- `client/` 的静态文件（html/css/js）在构建时**内联进 JS**（`globalThis.__BOMB_EMBEDDED_CLIENT__`），
  `serveStatic` 优先从内存取 —— 所以 exe **运行时不往磁盘写任何文件**，只有解析路径用到 `CLIENT_DIR`；
- `server/` 与 `lib/` 用 esbuild 打成**一个 CJS bundle**，作为 SEA 的 main；
- 双击（无参数）启动会切 UTF-8、自动打开浏览器；
- **能知道自己成功没有、也能关掉**：启动成功弹托盘气泡（含地址），`BombGame.exe --status`
  弹出状态窗（是否在跑 / 进程号 / 地址），`BombGame.exe --stop` 结束它；
- **单实例**：已经在跑的时候再双击，只会打开浏览器，不会又起一个看不见的进程；
- **启动失败不再"闪一下就消失"**：打印堆栈、写 `%LOCALAPPDATA%\BombGame\BombGame.log`、弹消息框，然后退出。

> 它**没有窗口**是设计取舍（省掉 Electron 那 200MB）。想要"有窗口、能点关闭"的桌面版，用下面的方式二（Tauri）。

打包机需要（玩家不需要）：`cd .build && npm install --ignore-scripts postject esbuild`。

> ⚠️ **杀软注意**：`BombGame.exe` 是"官方 node.exe + 注入启动代码"，注入会破坏它原本的
> Authenticode 签名，所以 Windows 会当成未知发布者（个别情况下 Defender 的启发式还会误报）。
> 现在的版本已经不释放文件了（去掉了最容易触发"释放器"启发式的行为），但**签名失效这一点无解**，
> 除非买代码签名证书。**要给别人的话，优先发"方式二"的绿色版**：里面的 `node.exe` 是 Node
> 官方原版、签名完好，基本不会被拦。

### 方式二：Tauri 桌面版（有窗口、能关、有安装包）

单个 exe 是**没有窗口**的（双击后只有浏览器 + 一个托盘气泡），如果你希望它像个正常桌面软件
——启动中窗口、失败原因窗口、关闭窗口就退出——用 Tauri 壳：

```
src-tauri/src/main.rs   启动内置 node 子进程 → 等端口可用 → 用真窗口加载 http://127.0.0.1:3210
src-tauri/tauri.conf.json  打包 node.exe 与 server/lib/client 为资源
.github/workflows/tauri-windows.yml  在 GitHub 的 Windows runner 上编译（本机不需要 Rust）
```

**本机没 Rust 也能出安装包**（推荐这条路）：仓库 → **Actions** → `tauri-windows` → **Run workflow**。
CI 会：跑二维码自检 → 准备内置 node.exe → `cargo tauri icon` → `cargo tauri build` →
上传 `BombGame-桌面版.exe`、NSIS 安装包、MSI 三个产物。打 `v*` tag 时会自动挂到 Release。

本机有 Rust（+ MSVC 构建工具）时也可以直接：

```bash
npm run tauri:assets     # 复制 node.exe 与游戏文件到 src-tauri/bundle-assets/
npm run tauri:icon       # 生成 512x512 图标（自己画的 PNG，无依赖）
cd src-tauri && cargo tauri dev      # 开发运行
cd src-tauri && cargo tauri build    # 出安装包
```

> 为什么这个壳值得做：单文件 exe 之前有个真实的坑 —— 用户双击后**看不出有没有成功，也没法关掉**，
> 反复双击还会留下好几个看不见的 `node.exe` 进程。Tauri 版把状态和退出都摆到窗口里了。
> 另外单文件 exe 现在也补了 `--status` / `--stop` 和单实例保护（见方式一）。

### 方式三：Windows 绿色版（**最好发这个**，原生 node.exe 不改动）

一条命令打包，产物是**自带 Node 运行时**的压缩包，对方解压双击 `play.cmd` 就能玩：

```bash
node tools/build-portable.mjs
# -> dist/BombGame-win-x64/       （目录，约 91 MB）
# -> dist/BombGame-win-x64.zip    （压缩包，约 35 MB，48 个文件）
```

包里有：`node\node.exe`（Node 运行时）+ `play.cmd`（启动器，会把自带的 node 塞进 PATH，再调用
`start.ps1`，所以端口、后台模式、自动开浏览器这些功能全都在）+ `使用说明.txt`。

玩家只要：**解压 → 双击 `play.cmd` → 浏览器自动打开 → 把窗口里打印的局域网地址和房间号发给朋友**。
不需要装 Node、不需要 `npm install`（本项目零依赖）、不需要联网下载任何东西。

几个实际会遇到的情况都写进 `使用说明.txt` 了：SmartScreen 提示、防火墙放行、端口被占用
（`play.cmd 8080`）、异地怎么玩。

> 打包机的 Node 版本就是玩家用的版本（直接取 `process.execPath`）。
> `dist/` 已在 `.gitignore` 里，90 MB 的 node.exe 不会进仓库。

### Cloudflare Workers + Durable Objects（把游戏本体搬到云上）

这是**唯一能让"服务端"也上云**的托管方案（EdgeOne/Pages 只能放静态客户端）：

```
cloudflare/src/index.js     Worker：路由 + CORS + 分配房间号 + 静态资源
cloudflare/src/room-do.js   Durable Object：一个房间一个实例，内部就是 new Game()
cloudflare/wrangler.toml    DO 绑定 / SQLite 存储 / [assets] 静态资源
```

为什么能这么省事：`lib/*` **零 Node 依赖**，`server/room.js` 只用了 `crypto.randomBytes`
（Workers 开 `nodejs_compat` 就支持），所以**游戏逻辑一行不用改**，只重写传输层
（`node:http` → `fetch` + `ReadableStream` 的 SSE）。客户端也完全不用改。

```bash
node tools/build-static-site.mjs        # 生成 site/（静态客户端）
cd cloudflare && wrangler deploy        # 需要 wrangler login
```

客户端指向它：`https://你的静态页/?server=https://bomb.mifan.eu.cc`

> 默认对外地址就是 **<https://bomb.mifan.eu.cc>**（Worker 绑的自定义域名，在 `wrangler.toml` 的 `routes` 里）。
> 想换地址就改那一条，同时把 `functions/api/[[path]].js` 里的 `DEFAULT_ORIGIN` 一起改。

> **注意**：Durable Objects 属于 Workers 付费计划（$5/月起，免费计划是否包含以控制台为准）；
> DO 空闲会被驱逐，没人连着时房间状态会丢（本地版也是内存态）。
> **国内可达性**：`*.workers.dev` / `*.pages.dev` 在国内经常不稳定，要稳定得绑自定义域名。
>
> 本地就能验证移植是否正确（不需要 Cloudflare 账号）：`node tests/cloudflare.mjs`
> —— 它把 DO 直接实例化，跑建房/加入/开始/权限/SSE/404，全绿。

### 静态托管（EdgeOne Pages / GitHub Pages）：放客户端，API 打回房主

先说清楚一个容易误会的地方：**localStorage 不能用来同步房间**。它是「每个设备、每个域名各自一份」，
两台手机就算填同一个房间号，也是两个互不相干的缓存 —— 房间号只是个标签，没有传输通道。
房间状态、倒计时、失误次数、模块判定**必须有一处共享的存储**，这就是服务端存在的原因。

但静态托管依然很有用：把**客户端页面**放到国内访问快的 CDN（EdgeOne Pages 比 GitHub Pages 稳），
让页面的 `/api/*` 与 SSE **跨域打回房主那台机器**（局域网地址或隧道地址）。服务端已经开了 CORS。

```bash
node tools/build-static-site.mjs      # -> site/（index.html + static/*）
```

EdgeOne Pages 配置：**构建命令** `node tools/build-static-site.mjs`，**输出目录** `site`，
框架选"静态/其他"。部署完打开时带上房主地址（会记住，之后不用再填）：

```
https://你的域名.edgeone.app/?server=https://xxxx.trycloudflare.com
```

也可以先在页面里填（静态托管版会显示「连接到房主的游戏」）。
**大厅里的邀请二维码会自动带上 `&server=`**，所以朋友扫码进来也能自己连上房主 —— 这点有测试守着。

> 想彻底摆脱"房主电脑必须开着"：
> ① 把服务端部署到云主机（`Dockerfile`，最稳）；② 把服务端搬到边缘函数 + KV（要重写，SSE 改轮询）；
> ③ 改成浏览器 P2P（WebRTC，房主的浏览器当服务端，同样是一次重写）。

### 方式四：公网在线版（发个链接就能玩，异地也行）

服务端读 `PORT` 环境变量、支持 `BOMB_ADMIN_TOKEN`，所以任何能跑容器的平台都能直接部署：

```bash
docker build -t bombsite .
docker run -d --name bombsite -p 3210:3210 -e BOMB_ADMIN_TOKEN=换成你的令牌 bombsite
```

放到 Render / Railway / Fly / Zeabur / 自己的 VPS 都可以，平台一般会帮你配好 HTTPS。
注意两点：**只能跑 1 个实例**（房间状态在内存里，多副本之间不共享房间）；建议用
`BOMB_ADMIN_TOKEN` 固定管理令牌，否则每次重启都会变。

### 方式五：微信小程序 —— 目前做不了，原因是硬门槛

不是技术实现不了，是平台规则卡死，具体三条：

1. **类目与版号**：个人主体的小程序**选不了「游戏」类目**；游戏类目需要企业主体 + 广电总局的
   网络游戏出版物号（版号）。所以"小游戏"这条路个人开发者走不通。
2. **域名必须备案**：小程序的 `wx.request` / `wx.connectSocket` 只能请求**已 ICP 备案的
   HTTPS/WSS 域名**，而且要在后台配进白名单。**局域网 IP 一律不允许** —— 这正好掐死了本游戏
   最核心的"同一张桌子、各看各的屏幕"玩法。
3. **没有 SSE**：小程序的网络层没有 `EventSource`，现在的实时推送（`GET /api/events`）得改成
   WebSocket 重写传输层。

所以想在微信里分享给朋友，实际可行的做法是**方式二的公网版**：把服务部署到有备案域名的机器上，
把链接发到微信里，对方点开就是浏览器 H5，扫码/点链接即玩。真要做小程序，需要企业主体 + 版号 +
备案域名 + WebSocket 改造，不是加个壳的事。

### 为什么没选 Electron？

Electron 能让房主"双击一个真正的桌面 App"，但代价是：

- 体积从 **35 MB 涨到 200 MB+**（Electron 自带 Chromium）；
- **只改善房主那一端** —— 其他玩家本来就只能用手机/电脑浏览器打开，一点没变；
- 还得处理签名、自动更新、杀毒误报。

同样的"原生感"用更便宜的方式就够了：单文件 exe（91 MB）+ 自动开浏览器；要更小可以上 Tauri
（用系统 WebView2，10 MB 级别），但需要 Rust 工具链。真正对"分享给别人玩"有帮助的其实是
**局域网二维码**：房主大厅显示一个二维码，朋友扫一下就进房间，比手打 4 位房间号顺手得多。

## 三条给玩家的建议

1. **拆弹者要"话多"**：不要只说「有线」，要说「从上到下一共四根：红、带白条纹的蓝、黄、黑」。
2. **专家要"问得准"**：先问清外壳信息（序列号含不含元音、末位奇偶、电池数、指示灯、端口），再查表。
3. **用文字频道兜底**：有人不方便说话时，把关键信息打字发出来，比划手势容易出错。
